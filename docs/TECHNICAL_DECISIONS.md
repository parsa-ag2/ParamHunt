# TECHNICAL_DECISIONS.md

ADR-style records. Status: **Accepted / Proposed / Superseded**. Each records the decision, alternatives, and the risk accepted.

## #1 — WXT as the extension framework — **Accepted**

- **Decision:** [WXT](https://wxt.dev) (Vite-based) over manual manifest + bundler wiring, or CRXJS.
- **Why:** auto-generates MV3 manifest from typed config; first-class entrypoints (background/content/popup/options/devtools); HMR for content scripts; active maintenance (verified live: `wxt-dev/wxt` v0.21.x, React 19 templates); TS-native.
- **Alternatives:** manual Vite (max control, but manifest/entry plumbing becomes our maintenance); CRXJS (`@crxjs/vite-plugin` — long-lived beta status, stalled maintenance windows; risk accepted by some, we reject for a long-lived tool). Both remain escape hatches: WXT outputs a plain MV3 bundle; nothing binds us beyond config.
- **Risk:** framework version churn — mitigated: pin wxt minor, generated manifest reviewed in CI diff.

## #2 — React 19 + Tailwind CSS 4 — **Accepted**

- React for the three UI surfaces (popup/options/panel); component model matches findings-table + filters work. Verified live: wxt react template ships react ^19.2.4.
- Tailwind v4 (CSS-first, `@tailwindcss/vite` plugin) — no config-file drift, dark-first UI cheap. Alternative (MUI/antd) rejected: heavy for a panel; custom design language preferred for a security tool.

## #3 — Modular monolith with plugin contracts — **Accepted**

- One typed `ModuleDefinition` contract + registry; modules never import each other; engine owns lifecycle/errors/state authority. Rejected: runtime-loaded plugin system (MV3 no-remote-code makes it pointless), per-module contexts (impossible in MV3).
- **Growth guarantee:** new module = folder + registration; no engine edits (see SYSTEM_ARCHITECTURE §2).

## #4 — Background owns storage via a `StorageAdapter` port — **Accepted**

- Hexagonal seam: modules/UI never touch `chrome.storage`; swap-in-memory fake for tests; IndexedDB backend possible later for large datasets (chrome.storage.local quota 10 MB default).
- Only the background writes storage (no cross-context write races).

## #5 — DevTools panel is the primary workbench — **Accepted**

- Popup dies on close and is ~800px wide at best; the devtools panel lives for the whole inspection session, is full-width, sits in the researcher's native environment, and can use devtools-context APIs (`devtools.network`, `getEventListeners`, `inspectedWindow`). Popup = status/toggles only.

## #6 — Permission minimization (list) — **Accepted**

- Granted now: storage, scripting, webRequest, tabs, activeTab, cookies. Rejected: downloads (blob export instead), declarativeNetRequest (we never block), webRequestBlocking (MV2-only), history/bookmarks/identity (unrelated), debugger (deferred to M3 deep-capture toggle — infobar banner cost documented).
- `<all_urls>` host permission: needed because the researcher chooses arbitrary in-scope targets; in-app scope allowlist is the real gate. Open question (M3): optional per-site host permissions UX.

## #7 — ULID/uuid for finding ids, sha-256 dedup hash — **Accepted**

- ids: `crypto.randomUUID()` (available in SW + pages, modern contexts). Dedup: `sha-256(source|type|location|canonical-detail)` via `crypto.subtle` — SW + devtools contexts have WebCrypto.

## #8 — Observational-only philosophy — **Accepted**

- The extension never sends attack payloads, never blocks/rewrites traffic, never auto-submits forms. Guessing/differential testing (Arjun/parameth-style) stays in external tooling; ParamHunt merges its *results* with browser-observed data.

## #9 — MAIN-world access via registered content script (`world: "MAIN"`) — **Accepted**

- For postmessage-tracker/event hooks. Rejected: `eval`/`Function` injection (CSP/standards violation), remote script injection (MV3 forbidden), tabs.executeScript legacy path (deprecated UX).
- Channel MAIN↔isolated: `window.postMessage` + per-session token + exact-origin check (docs/COMPONENT_COMMUNICATION §3.3).

## #10 — Message protocol as single discriminated union — **Accepted**

- All cross-context messages typed in one file (`core/messaging/protocol.ts`); `assertNever` exhaustiveness; requestId correlation; response envelopes. Rejected: per-feature message namespaces (string drift), event-only architecture (need request/response for queries).

## #11 — Icons are generated placeholders — **Accepted (temporary)**

- Flat placeholder PNGs (16/32/48/128) generated by script; real logo pending design. Not blocking: manifest requires valid PNGs only.

## #12 — Official-docs verification pass pending — **Open**

- Research-phase network restriction (developer.chrome.com unreachable from this vantage, 2026-11-17): doc-derived facts are annotated `TODO(verify)` in code/docs. List: SW lifecycle details, messaging lastError specifics, `world: "MAIN"` registration syntax, wxt devtools entry naming. Gate: before M0 completion.

## #13 — CI as architecture guard — **Accepted**

- GitHub Actions: `npm ci → tsc --noEmit → vitest → wxt build`. Future: manifest diff review, dependency-review action, artifact upload of built zip.
